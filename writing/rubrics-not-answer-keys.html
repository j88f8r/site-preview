Rubrics, Not Answer Keys: Testing AI for School Psychology

Some of the hardest calls in my job are special education eligibility decisions. A team makes them, after weeks of testing, observation, and talks with the family and teachers. I’ve been building a local-first decision-support tool for psychologists, meant to help that team check its reasoning. It does not make the call. Before a tool like that gets near a real case, I need a way to know whether it helps. This is how I set that up.

Start with where the data lives. Student records are protected under FERPA and California privacy law. So the tool runs on the psychologist’s own laptop, and case material never goes to a cloud service. Test cases stay on the device too, or they’re synthetic. That choice limits which models I can use and how fast they run, and the evaluation has to live with the same limits.

Don’t ask a bigger model to grade the answer. For expert reasoning, a model good enough to judge an answer is about as hard to build as the model giving it. Chai Asawa made this point in his AI Engineer World’s Fair talk on how Abridge evaluates medical decision support. The reference has to come from people who do the work.

Use rubrics, not answer keys. Two good psychologists can reach the same decision by different routes. So the reference for each case is a list of things a sound analysis should cover, not one correct paragraph. The tool is scored on whether its output covers those things.

Build each rubric with four people. Two psychologists write rubrics on their own. A third settles where they disagree. A fourth, who wrote none of it, checks the final version. I adapted this from the process Abridge has described in public. One rule sits on top: AI never writes the answer key. The system being tested can’t author its own reference.

Weight recall. Missing a real consideration about a child costs more than raising one the team can dismiss in a few seconds. So scoring favors recall. I still report precision, and I say which number matters more instead of hiding both inside one blended score.

Check for bias with paired cases. Special education has a long, litigated history of racial and linguistic disproportionality. So the evaluation includes pairs of synthetic cases that are identical except for gender, ethnicity, or home language. If the output changes when only that detail changes, that’s a signal worth reading. Models are noisy, though. So before reading any single difference as bias, I run the same case many times to see how much the output moves on its own. That rule is written down before any results come in.

Write the plan down before measuring. Scoring rules, pass bars, and expected failure modes go in a public document before results exist. It’s the same reason medical trials pre-register. If I pick the metrics after I see the numbers, I can make almost anything look good.

Keep a person in charge, on purpose. Federal special education law makes eligibility a team decision. The tool shows evidence before conclusions, and a psychologist always makes the call. The evaluation asks whether the team’s reasoning gets better, not whether the tool could replace the team.

Questions any school team can ask about an AI tool:

  • Who wrote the reference it was tested against, and were they psychologists?
  • Was the scoring plan written before the results?
  • Was it checked for different answers across groups of students?
  • Where does student data go?
  • What is it not meant to do, and is that written where users will see it?

Where this stands: the method is public and the tool is a prototype. There are no pilot results. If you’re a school psychologist and want to help build rubrics, I’d like to hear from you.
